# StockShotManager 1.9

版本号：1.9（versionCode 10）。提供 A、B、C、D 四个可同时安装的程序，功能相同，数据库和设置独立。

| 版本 | 包名 | Downloads 下默认截图目录 |
| --- | --- | --- |
| A | com.stockshot.manager | StockScreenshots |
| B | com.stockshot.manager.b | StockScreenshotsB |
| C | com.stockshot.manager.c | StockScreenshotsC |
| D | com.stockshot.manager.d | StockScreenshotsD |

## v1.9 修复与诊断日志

- 最高价查询在东方财富请求失败时自动使用备用行情源：沪深使用腾讯不复权日 K，北交所使用新浪近期日 K。保留股票身份、价格及区间校验；任一分段失败时不写入部分最高价。
- 北交所备用接口最多返回近期 1023 根日 K，程序会检查区间覆盖。历史起点不覆盖或停牌末端等情况无法确认完整行情时明确报错并保留原价。
- 更新完成后显示详细结果，列出失败股票和原因；主菜单“上次最高价结果”可以重新查看本次页面会话内的结果。
- 主菜单及设置页均提供“诊断日志”，开关即时生效并独立保存，默认关闭。关闭后保留已有日志，仍可查看、复制预览、导出完整日志、通过系统分享或清空。
- 日志包含程序版本、设备与系统信息、股票代码、查询日期、数据源、HTTP 状态、耗时、响应摘要及异常堆栈。保存在本机私有目录，最多保留约 1.5 MiB；不会自动发送。四个版本的日志各自独立。
- 排查步骤：打开“诊断日志”并开启 → 再次执行“更新最高价” → 返回日志窗口刷新 → 导出或分享日志文件。排查结束可随时关闭。

## v1.8 功能

- 主页面菜单新增“更新最高价”。最大天数每次默认 10，可输入正整数；例如记录日期为 9 月 1 日，输入 10，则统计 9 月 2 日至 9 月 11 日的最高价，不包含记录当天。
- 使用东方财富不复权日 K 的最高价，区间未结束时统计已有行情。成功结果覆盖卖出价；无行情或请求失败保留原价，并在结束时汇总数量。
- 最高价更新覆盖所选日期的全部股票，包括“只看标记”隐藏的股票；同一股票、同一天的全部截图同步更新，每张截图按自身买入价重算收益。
- “获取当日列表”保存到页面所选日期。采集弹窗显示目标日期，任务启动后切换页面日期不会改变归属日期。
- 修复停止后快速重新采集时，上一轮清理动作可能使新一轮录屏失效的问题。
- 主列表与搜索结果末尾新增“备注”。点击可多行编辑、保存、取消或清空；同股票同日期的截图共享备注，再次采集会继承已有内容。
- 序号和名称左侧的列固定，从买入列开始横向滑动；备注宽度等于买入、卖出列宽之和，其余列保持原有宽度。名称和备注换行时整行增高。
- 数据库从版本 1 迁移到版本 2，保留旧记录并为旧记录填入空备注。备份与 CSV 支持备注、换行、逗号和引号；缺少备注的旧文件仍可导入。
- 系统无障碍设置中的服务名称带有 A/B/C/D 标识。二维码共享设置不覆盖各版本的截图目录。

## 构建与验证

自 2026-11-25 起，使用 GitHub Actions 和 JDK 17 同时生成四个签名 Release APK，配置与下载见 GITHUB_BUILD.md。原 build-apk.bat 留作历史本地构建脚本。
构建脚本检查包名、版本、签名有效性及四包证书一致性，全部通过后导出同一时间戳副本及 `StockShotManager-{A|B|C|D}-release-latest.apk`。

单元测试与 Release lint 的执行方法见 BUILD_NOTES.md。测试覆盖自然日区间、沪深北行情解析、备用源切换与数据覆盖、部分失败、并发限制、日志开关/轮转/导出/错误处理、日志分享文件权限、旧数据库迁移、逐截图收益、备注继承与清空、恢复事务回滚、备份/CSV 往返及采集快速重启。

本次构建环境没有连接 Android 设备。历史日期实际采集、授权流程、长备注布局、滑动/长按/多选及四版同时安装仍需实机验收。
